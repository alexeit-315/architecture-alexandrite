Перечень проблем
1. О проблемах в системе становится известно от пользователей, когда технические проблемы уже перешли в плоскость бизнес-проблем;
2. У системы несколько различных Use case, неизвестно при выполнении каких из них и в каких местах возникают ошибки; Жалобы касаются конечной цели - невыполнения заказов;
3. Нет canary-релизов / использования feature flags, баги в проде обнаруживаются на полном потоке запросов;
4. Ручное тестирование тормозит релизы;
5. С ростом нагрузки на систему увеличилось количество жалоб со стороны пользователей системы о невыполнении заказов (отказы), но неизвестно, как отказы распределены между пользователями разных типов (Customer, Seller, API user), каков процент отказов, растет он или стабилен;
6. Операторы (Operator) жалуются на медленную работу интерфейса MES;
7. Долгий расчёт стоимости (до 30 минут).

Возможный перечень проблемных мест
1. Перегруженность инфраструктуры;
2. MES тормозит при загрузке списка заказов, а пагинация и фильтры не решают проблему - скорее всего, неоптимизированы запросы к БД;
3. Долгий расчёт стоимости (до 30 минут) в MES - подсистема не масштабируется при высокой нагрузке, нет очередей передачи запросов для обработки сложных расчётов внутри подсистемы;
3. Используется один инстанс БД на чтение и запись - высокая нагрузка, возможны блокировки;
4. Потеря заказов - RabbitMQ без отказоустойчивости, при падении очереди заказы между MES и CRM теряются;
5. Жалобы на просрочки - нет системы мониторинга SLA и автоматического оповещения о задержках;
6. API для партнёров нестабилен - нет rate-limiting, нет механизма повторных попыток;
7. Использование синхронных вызовов в MES при длительном (до 30 минут) расчете стоимости. 

Инициативы для устранения нежелательных ситуаций
1. Реализовать сбор бизнес метрик для оценки результатов поддерживаемых системой процессов;
2. Реализовать сбор технических метрик для оценки качества работы системы;
3. Реализовать визуализацию метрик;
4. Реализовать трассировку выполнения операций для основных Use Case;
5. Настроить логирование работы основных подсистем;
6. Настроить кэширование, read-replicas для ускорения работы приложений;
7. Настроить паттерны снижения нагрузки при перегрузке приложений (rate-limiting, backpressure, circuit breaker);
8. Реализовать автоматизацию E2E-тестов;
9. Реализовать дашборд для мониторинга SLA по заказам;
10. Реализовать отказоустойчивость RabbitMQ между MES и CRM
11. Реализовать асинхронное взамодействие внутри MES
12. Выделить расчёт стоимости в MES в отдельный микросервис
13. Реализовать canary-деплой

Критерии приоритезации инициатив:
1. Критичность для бизнеса (потеря клиентов -> срочно).
2. Влияние на масштабируемость (рост нагрузки -> нужно решать сейчас).
3. Быстрые в реализации (быстрые победы vs долгие проекты).

Топ-3 инициативы на ближайшие полгода:
1. Мониторинг, трассировку и алертинг на основе метрик (Prometheus + Grafana) -> Позволит заранее выявлять проблемы, а не ждать жалоб;
2. Оптимизация MES и БД (кэширование, read-replicas) -> Уменьшит жалобы операторов и ускорит работу;
3. Выделение расчета стоимости в отдельный сервис в MES и организация асинхронного обращения к нему через очереди (Kafka) -> Решит проблему с долгими расчётами стоимости (особенно для API-партнёров).

Целевая архитектура через полгода:
1. MES: Разделение на микросервисы (выделение расчёта стоимости в отдельный сервис)
2. БД: Read-replicas
Интеграции: Dead letter queue
CI/CD: Автоматические тесты, canary-деплой
Мониторинг: Дашборды SLA по заказам.
