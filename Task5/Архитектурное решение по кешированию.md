## Мотивация
Проблемы, которые решит внедрение логирования:
1. Снижение времени на разбор инцидентов 
2. Прозрачность процессов для всех команд (разработка, поддержка, менеджмент)
3. Автоматическое выявление аномалий (DDoS, сбои интеграций)

Метрики решения, на которые влияет в сторону улучшения внедрение логирования:
1. MTTR (Mean Time to Repair) — среднее время восстановления (техническая метрика)
2. Количество тикетов в поддержку (бизнес-метрика)
3. Выполнение SLA ответа поддержки (бизнес-метрика)
4. Выполнение SLA выполнения заказа (бизнес-метрика)

### Приоритеты реализации логирования для модулей
Первая очередь (критично):  

| **Система**                  | **Собираемые логи**                             | **Уровень** | **Комментарии**                                      |
|:-----------------------------|:------------------------------------------------|:------------|:-----------------------------------------------------|
| MES API                      | Изменение статусов                              | INFO        | Влияет на SLA                                        |
| MES Cost calculation service | Расчет стоимости                                | INFO        | Значительная часть ошибок                            |
| RabbitMQ                     | Потеря сообщений, dead-letter-queue             | WARN        | Потеря заказов                                       |
| CRM API                      | Подтверждение заказов, ошибки валидации заказов | INFO/ERROR  | Влияет на SLA                                        |
| System logging               | Загрузка системных ресурсов                     | WARN        | Влияет на быстродействие и работоспособность системы |

Вторая очередь:

| **Система**      | **Собираемые логи**                                                                              | **Уровень** | **Комментарии** |
|:-----------------|:-------------------------------------------------------------------------------------------------|:----------|:----------------|
| Shop API         | Создание заказов, оплата                                                                         | INFO      |                 |
| 3D Storage       | Ошибки загрузки файлов                                                                           | WARN      |                 |
| Security logging | Успешная/неуспешная аутентификация, изменение прав доступа, попытки несанкционированного доступа | INFO/WARN |                 |

## Предлагаемое решение
Используемая технология:

| **Компонент**  | **Технология**     | **Роль**                                                        |
|:---------------|:-------------------|:----------------------------------------------------------------|
| Сбор логов     | Filebeat           | Легковесный агент для сбора логов с файлов и системных журналов |
| Обработка      | Logstash           | Фильтрация, парсинг, маскировка ПдН, обогащение логов           |
| Хранение/поиск | Elasticsearch      | Индексация логов (по order_id, trace_id, timestamp)             |
| Визуализация   | Kibana             | Дашборды, анализ логов, создание правил алертинга               |
| Безопасность   | Elasticsearch RBAC | Контроль доступа к логам                                        |

## Безопасность
Предлагаемые меры:
- Ролевая модель:
  - supports — только просмотр
  - managers — только просмотр
  - devops — только просмотр
- При сохранении данных в логи будет осуществляться маскировка ПдН

## Политика хранения
Хранение логов будет осуществляться в отдельном индексе со сроком хранения:

| **Тип логов**         | **Срок** | **Индекс в Elasticsearch** | **Архивация** |
|:----------------------|:---------|:---------------------------|:--------------|
| Логи безопасности     | 360 дней | `logs-security-*`          | S3            |
| Ошибки (ERROR)        | 30 дней  | `logs-error-*`             | -             |
| Предупреждения (WARN) | 30 дней  | `logs-warn-*`              | -             |
| Бизнес-логи (INFO)    | 14 дней  | `logs-info-*`              | Удаление      |
| Дебаг-логи (DEBUG)    | 1 день   | `logs-debug-*`             | Удаление      |


## Анализ и алертинг
### Перечень алертов на основе логов

#### 1. API и бизнес-метрики
| №   | Метрика                           | Условие срабатывания                                            | Уровень | Действия                                                 | Интеграции                      |
|-----|-----------------------------------|-----------------------------------------------------------------|---------|----------------------------------------------------------|---------------------------------|
| 1.1 | Превышение времени ответа MES API | `latency{endpoint="/calculate_cost"} > 15m (B2C) или >5m (B2B)` | Critical | Алерт поддержке, автомасштабирование MES                 | Kibana -> Notification service  |
| 1.2 | Ошибки 500 в MES API              | `rate(http_requests{status="500",service="mes"}[1h]) > 5`       | High | Алерт поддержке                                          | Kibana -> Notification service  |

| 1.4 | Нарушение SLA расчета стоимости   | `time_to_calculate{order_type="custom"} > SLA`                  | High | Алерт поддержке, уведомление менеджеров + дамп контекста | Kibana -> Notification service  |

## Критерии выбора технологии логирования

| № | Критерий           | ELK                                         | OpenSearch                  | Splunk                      | Graylog                   |
|---|--------------------|---------------------------------------------|-----------------------------|-----------------------------|---------------------------|
| 1 | Тип лицензии       | Elastic License / SSPL                      | Apache License, Version 2.0 | Проприетарная               | GNU GPLv3                 |
| 2 | Производительность | Высокая скорость индексации (Elasticsearch) | На 15-20% медленнее ELK     | Оптимизирована под big data | Средняя, зависит от MongoDB |
| 3 | Гибкость           | Поддержка сложных запросов (KQL в Kibana)   | Полная совместимость с ES API | SPL-язык с AI-аналитикой    | Pipeline-правила на Groovy |
| 4 | Безопасность       | RBAC, TLS, маскировка ПдН                   | Аналогично ELK + плагины    | Enterprise-класса (PCI DSS) | Базовый RBAC + HTTPS       |
| 5 | Стоимость          | Бесплатен (Community Edition)               | Полностью open-source       | От $150/GB в день           | Бесплатен (Open Core)      |
| 6 | Интеграции         | Prometheus, Grafana, Jira                   | AWS-сервисы, Kafka          | 2000+ готовых коннекторов   | SIEM-системы, Webhooks    |
| 7 | Масштабируемость   | До 100+ узлов в кластере                    | Лучше работает в облаке     | Горизонтальное масштабирование | Ограничена MongoDB        |
| 8 | Обучение           | Обширная документация                       | Совместим с ES-туториалами  | Сертификационные программы  | Минимум порога входа      |
| 9 | Хранение данных    | Hot-Warm-Cold архитектура                   | Аналогично ELK              | SmartStore (S3-бэкенд)      | Зависит от СУБД           |
| 10| Поддержка          | Коммерческая (Elastic)                      | Сообщество + AWS            | 24/7 Enterprise Support     | Комьюнити + платные опции |

**Результат сравнения:**
1. Для **cloud-развертывания**: OpenSearch (полная AWS-интеграция)
2. Для **комплаенс-проектов**: Splunk (готовые шаблоны для PCI DSS/GDPR)
3. Для **бюджетных решений**: Graylog (проще в развертывании, чем ELK)
4. Для **гибридных сред**: ELK (лучшая поддержка on-premise + cloud)
